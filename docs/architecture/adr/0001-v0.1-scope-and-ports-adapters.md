# ADR 0001: v0.1 scope and ports-and-adapters architecture

- Status: Accepted
- Date: 2026-08-08

## Context

Agent memory spans incompatible forms, functions, lifecycles, providers, storage engines, and benchmarks. Implementing every branch at once would obscure the research variables and make evaluation claims difficult to audit.

## Decision

v0.1 implements explicit token-level, flat memory for factual, experiential, and working functions. Each function covers formation, evolution, and retrieval. Graph/hierarchical organization and latent/parametric execution are deferred.

The Go monorepo uses lightweight ports and adapters:

- `domain` defines memory meaning and invariants.
- `application` defines use-case contracts and policies.
- inbound adapters map CLI, HTTP, MCP, Go SDK, and AgentEvent onto those contracts.
- outbound adapters implement SQLite, artifacts, providers, clocks, identifiers, and telemetry.

The domain/application core must not import transport, database, MCP, Ollama, or cloud-provider packages. No ORM, dependency-injection framework, or agent framework is used. One `memxplore serve` process owns mutable operational state.

## Consequences

The architecture favors auditability and contract tests over rapid framework-driven assembly. Some research forms are represented in the catalog and roadmap but not executable in v0.1. Adapter wiring remains explicit and may be more verbose.
